# PS5X360 v0.5.1-preview - disc images and packages read from the file

Development build. Not published.

## Changes

- **ISO, STFS and GOD/SVOD data is read with `pread` on the console.** The core maps each disc
  image or package file whole and copies file data out of the mapping. On the console every page
  read that way stays mapped into the title. `MappedMemory::ReadAt` now reads the file itself on
  the PS5 (and on a PC when `XE_MAPPED_READ_FILE` is set); directory parsing and executable
  loading still use the mapping, which touches little of it.
- **Kernel-call boundary.** Only `std::exception` is caught. The catch-all added in 0.5.0 also
  caught the forced unwinding glibc uses to end a thread (`FATAL: exception not rethrown` on the
  host runner when a guest thread exited).
- **`tools/make-test-iso.py`** packs an extracted game folder into an XDVDFS image at offset 0.

## Why

Community reports for 0.1.0-preview describe ISO, GOD and XBLA titles that load part of the way
and then freeze the whole console (GitHub #2, #4, #7, #8, #9, #11), on firmware 5.02, 13.20 and
13.60, while extracted folders run on the development console. All three container formats copy
data out of whole-file mappings; extracted folders are read with file calls. That the mapping is
the cause is a hypothesis: no container format had been run on the development console when this
was written, and those reports are from an older build.

## Verification

- Host: a 2.78 GB image made from an extracted game (Ben 10 Alien Force: Vilgax Attacks) mounted,
  launched and reached gameplay on the PC runner through the `pread` path (75 s, 1425 refreshed
  outputs, audio present). Without the kernel-call change the same run aborted when a guest
  thread exited.
- Native compilation and image validation passed; symbols in `build/symbols/0.5.1-preview`.
- Console: not yet run with an ISO, GOD or XBLA title.

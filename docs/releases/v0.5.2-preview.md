# PS5X360 v0.5.2-preview - disc images and packages are not mapped on the console

Tester build. Game compatibility is still being refined; see the verification limits below.

## Changes

- `MappedMemory::OpenForReading` opens a file to be read with `ReadAt`. On the PS5 nothing is
  mapped (`data()` is null, `Slice` gives another file view); elsewhere it maps as before, unless
  `XE_MAPPED_READ_FILE` is set to exercise the console path on a PC.
- `DiscImageDevice` verifies the volume and reads every directory table through `ReadAt` into
  buffers, with bounds checks on each entry; `DiscImageEntry` reports that it cannot be mapped
  when the image is not, so executables are loaded through the file reader.
- `StfsContainerDevice` and `SvodContainerDevice` read directory blocks, hash tables, layout
  magic and directory entries with `ReadAt`; a package opened for reading has its header read
  from the file. Packages opened for writing (saves, profiles) are mapped as before.

## Evidence

On the development console (firmware 13.60, games on an exFAT-listed volume), 0.5.1-preview was
given a 2.78 GB test image made from an extracted game. Its boot log ended at
`LOAD initialize device`, with no `LOAD device ready`, and stayed there for minutes: the title
stopped inside `DiscImageDevice::Initialize`, which at that point mapped the whole image and
parsed its directory through the mapping. The FTP payload on the console kept answering. This
is the stage at which community reports for ISO, GOD and XBLA titles describe a freeze. Whether
the mapping call or the first access to it stops is not known.

## Verification

- Host, with `XE_MAPPED_READ_FILE=1`: the same image mounted, launched and ran for 60 s (1294
  refreshed outputs). Host checks for file opening, content headers, utility cache, module
  paths, patch selection and upload pages passed with and without the variable.
- No STFS (XBLA) or SVOD (Games on Demand) sample was available: those readers are changed but
  not run with real content, on host or console.
- Native compilation and image validation passed; symbols in `build/symbols/0.5.2-preview`.
- Console (development PS5, firmware 13.60): the 2.78 GB test image that stopped 0.5.1-preview
  at `LOAD initialize device` reached `LOAD device ready` and `launch status 00000000` with this
  build, and the game was reported on screen by the user. One image of one game; other images,
  other firmwares and installations on other file systems are unverified.

## Also in this build since 0.4.9-preview

See the notes of 0.5.0-preview and 0.5.1-preview: caches moved out of the save storage, an
optional instruction info cache, exceptions handled at the kernel-call and launch boundaries,
validated console settings, no host thread pinning, the performance measurement in the guide.

## For testers

- Install by replacing the `PPSA50011` folder as before. Saves and profiles are kept; shader
  caches are rebuilt once.
- ISO images are expected to open now. Games on Demand and XBLA packages use the same new reading
  path but were not run by the developers: reports for them are especially useful.
- If a game does not open, the library may show the reason after it restarts. Send that text with
  `boot.log` and the game's log from this version (`tools/Download PS5 logs.bat`).
- Logs from older versions cannot be matched to this build's symbols.
